# Meteorite Atlas 1.2 — مشروع Android

مشروع Android أصلي بلغة Kotlin، يعرض مواقع النيازك المسجلة، ويضيف شاشة رصد للأحداث النارية الجوية اعتماداً على واجهة NASA/JPL CNEOS.

## الميزات الموجودة

- خريطة طرق OpenStreetMap، وصور أقمار Esri، وطبقة Hybrid للأسماء فوق الصور، وتضاريس OpenTopoMap.
- البحث في سجلات النيازك وعرض تفاصيلها وتجميع العلامات عند التصغير.
- استيراد CSV من منتقي ملفات Android، والتحقق من الإحداثيات، وحفظ البيانات محلياً في SQLite.
- إحصائيات أساسية للسجلات التي لها إحداثيات.
- زر **☄ الرادار** لجلب أحدث 100 حدث متاح ذي إحداثيات من NASA/JPL Fireball API.
- عرض علامات الأحداث على الخريطة، وقائمة بالأحداث، ووقت ذروة السطوع UTC، والإحداثيات، والارتفاع والطاقة عند توفرها.
- تخزين آخر استجابة للرادار محلياً، وعرضها إذا تعذر الاتصال لاحقاً.
- وضع اتصال/عدم اتصال يمنع طلب بلاطات خرائط جديدة؛ تبقى البيانات المحفوظة محلياً متاحة.

## تنبيه علمي مهم حول الرادار

هذه الميزة **ليست راداراً مستقلاً ولا بثاً لحظياً**. إنها تعرض أحداث الكرات النارية التي وصلت بياناتها إلى NASA/JPL من مستشعرات حكومية. توفر NASA تاريخ ووقت **ذروة السطوع**، والإحداثيات (عند توفرها)، والارتفاع والطاقة. إحداثيات ذروة السطوع ليست بالضرورة نقطة اصطدام أو موقع سقوط نيزك على الأرض. الخدمة تُحدّث بصورة غير منتظمة، ولا ترصد كل الشهب، ولا تتنبأ بمكان سقوط قطعة قبل وقوعه. لذلك لا تعرض الواجهة نقطة الحدث على أنها موقع سقوط مؤكد.

مصدر الرادار:
- https://ssd-api.jpl.nasa.gov/doc/fireball.html
- https://cneos.jpl.nasa.gov/fireballs/

## مصادر الخرائط والترخيص

- OpenStreetMap Mapnik للطرق.
- Esri World Imagery للأقمار الصناعية.
- CARTO Voyager labels لطبقة التسميات في Hybrid.
- OpenTopoMap للتضاريس.

تختلف شروط الاستخدام والإسناد لكل مزود. لا تنفّذ تنزيل بلاطات جماعياً من خوادم OSM القياسية، ولا تعتبر ذاكرة البلاطات التي زرتها تنزيل منطقة Offline كاملة. وضع Offline هنا يمنع تنزيل بلاطات جديدة ويعرض ما سبق تخزينه فقط. **لا يتضمن هذا الإصدار مدير تنزيل مناطق MBTiles أو ضمان عمل Hybrid كاملاً دون اتصال.**

## قاعدة النيازك

- المرجع الرسمي للأسماء والتصنيفات هو Meteoritical Bulletin Database: https://www.lpi.usra.edu/meteor/metbull.php
- يسمح التطبيق باستيراد CSV محلي. لا تُختلق الإحداثيات؛ لا تظهر على الخريطة إلا السجلات ذات الإحداثيات الصحيحة.
- مجموعة البيانات الاحتياطية التي ينزلها التطبيق ليست قاعدة MetBull الرسمية الحية. لإدخال أحدث بيانات 2025 و2026 يجب استيراد ملف حديث موثوق من المصدر الرسمي، والتحقق من أعمدته ومن السجلات ذات الإحداثيات.

## بناء APK عبر GitHub Actions

أضفت سير عمل تلقائياً في `.github/workflows/android-apk.yml`:

1. أنشئ مستودعاً جديداً في https://github.com.
2. فك ضغط ملف المشروع، ثم ارفع **محتويات مجلد `MeteoriteAtlasAndroid`** إلى جذر المستودع (لا ترفع ملف ZIP كملف وحيد).
3. تأكد أن `app/` و`build.gradle` و`settings.gradle` و`.github/workflows/` ظاهرة في جذر المستودع.
4. عند رفع الملفات إلى فرع `main` أو `master` يبدأ البناء تلقائياً. ويمكنك أيضاً فتح تبويب Actions واختيار **Build Android APK** ثم **Run workflow**.
5. بعد نجاح العملية، افتح عملية البناء ثم قسم **Artifacts** ونزّل `MeteoriteAtlas-debug-apk`. ستجد داخله `app-debug.apk`.

يتطلب البناء JDK 17 وGradle 8.9 وAndroid Gradle Plugin 8.6.1، وقد أُعد سير العمل لتجهيزها تلقائياً.

## نتائج الفحص وحدوده

- تم فحص محتويات المشروع وملفات XML وملف ZIP.
- تمت مراجعة منطق استجابة NASA حسب وثائق Fireball API (حقول `fields` و`data`، واتجاهات N/S وE/W).
- فحص Kotlin المحلي لم يُظهر أخطاء صياغة، لكن بيئة الفحص لا تحتوي Android SDK أو مكتبات AndroidX/osmdroid؛ لذلك لم يكن ممكناً تنفيذ Gradle build كامل أو تأكيد خلو التطبيق من أخطاء الربط/التشغيل.
- لم يتم اختبار APK على هاتف، ولم يتم اختبار اتصال التطبيق بخدمة NASA من داخل Android. يجب اعتبار نجاح GitHub Actions أول تأكيد بناء فعلي.
- لم يتم إرفاق CSV حديث من MetBull، لذا لم يتم التحقق من ملف بيانات 2025/2026 فعلي.
